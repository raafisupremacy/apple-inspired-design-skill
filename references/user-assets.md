# User-provided assets

Treat supplied images, screenshots, logos, video, and icons as authoritative project assets.

- Do not silently replace, fabricate, or materially alter them.
- Preserve the original and create derived crops, sizes, or compressed formats separately.
- Inspect dimensions, aspect ratio, transparency, orientation, quality, and file size before choosing a presentation.
- Choose crop, focal point, `contain`/`cover`, and responsive variants based on the asset’s purpose.
- Keep logos undistorted and unfiltered; keep important screenshot content intact.
- Add alt text or an accessibility label for informative media. Mark decorative media as decorative. If the content is unknown, ask or use a neutral description rather than inventing details.
- Do not transmit private images to external services or image-generation tools unless the user explicitly asks for that operation.
- If an asset is unsuitable, explain the limitation and offer a presentation or conversion path without changing its meaning.

## Meaning and differentiation

Distinguish entity-specific imagery, shared contextual imagery, and decorative imagery. Reuse is appropriate when the image genuinely describes the shared context; do not present one generic image as an accurate depiction of several distinct items. Check that the crop, caption, and alt text describe what the image actually shows rather than just repeating an adjacent title.

When distinct assets are unavailable, preserve supplied originals and use an explicitly illustrative treatment, a clear text-led presentation, or request the missing asset when it changes the design decision. Do not invent replacement photography. Evaluate image scale, focal point, and background across both overview and detail surfaces.
